# bandwagonhost sla：看懂 99.99% 在线率承诺、赔偿门槛和适用套餐

搜索 `bandwagonhost sla`，最需要先弄清楚的不是“搬瓦工所有 VPS 是否都有 SLA”，而是**你买的那一款是否明确包含 SLA**。BandwagonHost 官方协议只适用于产品页面明确标注 SLA 的套餐；普通、免费、试用或促销服务不自动适用。官方目前将 SLA 描述为按单台 VPS、按自然月计算的在线率承诺，并在符合条件时提供服务时长补偿，而非现金退款。

这一区别很实际：官网普通 VPS 页面展示了六款 KVM 套餐，但其公开套餐列表并没有把这些产品标为 SLA Plan。另有独立的 E-Commerce SLA 产品页面，官方说明目前只有美国洛杉矶 USCA_5 机房可提供 99.99% SLA。购买前应以具体产品页和订单配置页上的标注为准，不能只凭品牌、机房或价格推断服务受 SLA 覆盖。

## BandwagonHost SLA 到底承诺什么？

协议承诺：对每一台符合条件的 Covered VPS，BandwagonHost 会以商业上合理的努力，在每个自然月提供至少 **99.99% 月度在线率**，排除协议列出的情形后计算。这里的 Covered VPS，指属于 SLA Plan 且在相关自然月付费的 VPS。承诺按单台 VPS 计算，不是整个账户、所有服务或所有附加项目的统一保证。

99.99% 听起来很高，但它不是“服务器绝不会掉线”的保证。官方也明确说明，这是一项在线率目标和服务时长补偿机制，不保证服务没有中断或错误。按 30 天月份粗略换算，99.99% 对应约 4 分 19 秒的停机时间；而协议的补偿档位从**超过 4 分 32 秒**开始。实际判断看的是该自然月内的累计停机分钟数、适用排除项和服务商核验结果，不应把粗略换算当成赔偿自动触发器。

还有个容易误解的细节：协议中的“不可用”不是单纯指你的网站打不开，或某次 Ping 没响应。按定义，VPS 必须因服务商网络或物理宿主机问题，连续超过一分钟无法通过其标准网络连通性检查，并且内部监控确认故障不是由 SLA 排除项造成。仅 ICMP（Ping）被过滤、而 TCP 等正常业务仍可访问时，不算协议定义的不可用。

## 哪些停机不计入 SLA？

SLA 列出了一系列排除情形。即使用户确实遇到访问中断，也不代表这些时间一定计入可申请补偿的停机分钟数。

- **计划维护**：提前至少 24 小时通知的维护不计入。紧急维护在服务商合理降低影响、且该事件总中断不超过 10 分钟的情况下，也属于排除项。
- **用户自己的系统或配置**：操作系统、应用程序、脚本、数据、防火墙、路由、DNS、SSH 或 Web 服务配置引发的问题不计入。
- **资源限制和使用政策**：超出套餐设计或文档限制、触发公平使用规则、因服务条款或政策受到暂停、限速或限制的情况不计入。
- **攻击、安全问题和滥用**：DDoS 等攻击、因攻击采取的限流或黑洞措施、VPS 被入侵或感染恶意软件等情形均列为排除项。官方特别指出，SLA Plan 不包含 DDoS 过滤；遭遇攻击时，服务商可能临时封锁或黑洞处理相关 IP。
- **第三方网络问题**：上游运营商、互联网骨干网络、用户自己的网络，或服务商网络以外的访问路径问题不计入；被政府、监管机构或第三方屏蔽的 IP 也在排除范围内。
- **账户或不可抗力问题**：欠费、违反服务条款导致的限制，以及法律要求或超出合理控制范围的重大事件等，可能不计入。

对跨境业务来说，第三方网络这一条尤其值得留意。用户从某个地区访问缓慢，不一定等于服务商的 VPS 已按协议定义“不可用”。线路拥塞、跨网路由和用户本地网络体验，可能是实际业务问题，却未必满足 SLA 的补偿条件。

## 停机多久可以申请补偿？

只有在该 VPS 的月度在线率低于 99.99%、相关停机不完全由排除项解释，并且用户提交有效申请后，才可能获得服务时长补偿。协议列出的档位如下。

| 单台 Covered VPS 当月累计停机时间 | 可能获得的服务时长 |
| --- | ---: |
| 超过 4 分 32 秒且少于 10 分钟 | 12 小时 |
| 10–59 分钟 | 72 小时 |
| 60–119 分钟 | 120 小时 |
| 120–239 分钟 | 240 小时 |
| 240–419 分钟 | 360 小时 |
| 420 分钟或以上 | 该 VPS 一个月的预付服务时长 |

这些补偿不是现金，也不是退回账单金额，而是加到发生停机的那台 VPS 上的预付使用时间，例如延长续费或到期日期。补偿不能转到另一台 VPS 或另一个账户，也不适用于额外 IP、流量超额或其他附加费用。每台 Covered VPS 每个自然月的补偿上限为一个月预付服务时长。

因此，“99.99% SLA”更适合理解成有条件的服务时长补偿规则，而不是业务损失保险。如果短暂停机造成的损失远高于一个月 VPS 费用，协议提供的补偿方式和上限并不能覆盖这类损失。

## 如何提交 SLA 赔偿申请？

普通支持工单不等于 SLA 申请。用户需要通过服务商支持渠道联系对方，明确选择受影响的 Covered VPS，并在请求中清楚写明要申请 **“SLA Service Credit”**。申请至少应包括大致停机日期和时间、对 VPS 使用造成的影响；如果有监控截图、日志或 traceroute 等信息，也可一并提供。

申请可在故障结束后提交，但最迟必须在**停机发生所在自然月的最后一天之后 90 天内**送达，时区按加拿大温哥华时间计算。逾期可能被视为放弃该月申请资格。若你用自己的监控发现问题，建议先保存时间记录和证据；不过，官方监控、日志和系统记录是核定申请的重要依据，资料冲突时官方记录通常起主要作用，除非有明显错误或双方另有书面约定。

## 购买前核对清单

下单前，把以下几项逐一对照产品页与结账页面：

1. **套餐名称是否明确带 SLA**：协议以产品明确声明为准，而不是靠系列名称或营销描述推断。
2. **机房是否符合当前供应范围**：官方 SLA 产品页面目前指出 USCA_5 才提供 99.99% SLA。
3. **补偿形式是否符合预期**：补偿是加回受影响 VPS 的预付时间，不是现金退款，也不覆盖业务损失。
4. **排除项是否影响你的使用场景**：用户配置、DDoS、上游网络和第三方屏蔽等问题可能不计入。
5. **申请时限和措辞是否记清楚**：需要明确申请 “SLA Service Credit”，并在规定期限内提交。
6. **购买页的资源和最终价格**：库存和订单选项可能因套餐而异，本文普通 VPS 列表价格不能代替 SLA 产品的结账报价。
